# DNA Encoder

DNA Encoder is an experimental Python/PyTorch prototype for generating matrix-shaped tensors from coordinate-based Fourier features and a small neural network. Although the project metadata describes model compression, the current implementation does **not** encode or reconstruct a model's supplied weights.

## Status

This is an early-stage prototype, not a usable model-compression or model-checkpoint recovery tool. `DNAEncoder.encode(state_dict)` currently ignores `state_dict` and saves the encoder's own Fourier projection and network parameters. `decode()` generates values from those saved parameters; it does not recover the input weights. The repository contains no fitting or training routine that learns the generator from a model's weights.

## Implemented behavior

- `DNAEncoder` maps normalized two-dimensional coordinates through fixed random Fourier projections (`sin`/`cos` features) and a trainable multilayer perceptron with SiLU activations and a learned scale.
- `_generate_weight_matrix(out_dim, in_dim)` generates a matrix from that network. The implementation processes matrices in chunks when their element count exceeds `chunk_size` (default `16384`).
- `encode()` returns the generator's projection, network tensors, scale, and configuration; `decode(dna_state, target_shapes)` generates tensors for the requested shapes.
- `DNAEncoderWrapper` collects tensor shapes and the source model class name before delegating to the same generator-state encode/decode operations. Its `decode_model()` returns a dictionary of tensors, not an instantiated PyTorch model.
- `count_parameters()`, `compression_ratio()`, and `create_dna_encoder()` provide parameter counting, a parameter-count ratio, and a constructor helper.

For decoding, two-dimensional shapes are generated by the network, one-dimensional shapes are filled with zeros, and shapes with other ranks are not handled. `compression_ratio()` is only arithmetic based on trainable parameters: it excludes the fixed Fourier buffer and does not measure serialized size, reconstruction quality, or task accuracy. The repository provides no measured compression-quality, accuracy, or performance results.

## Requirements and running from a checkout

The project metadata requires Python 3.10 or later, PyTorch 2.0 or later, and NumPy 1.24 or later. From the repository root, install the listed dependencies:

```bash
python -m pip install -r requirements.txt
```

The module can be imported directly while running from the checkout. This small example generates a new matrix; it does not compress model weights:

```python
from dna_encoder import DNAEncoder

encoder = DNAEncoder(num_freqs=8, hidden_size=16, chunk_size=64)
dna_state = encoder.encode({})
generated = encoder.decode(dna_state, {"weight": (4, 3)})
print(generated["weight"].shape)  # torch.Size([4, 3])
```

There is no command-line interface. The project declares distribution metadata, but a wheel built from the checked-out configuration contained metadata only and omitted `dna_encoder.py`; installing that wheel therefore does not provide the importable module. Use the source checkout rather than treating the current wheel configuration as a working installation path.

## Limitations

- The given model state is not used by `encode()`; there is no implemented optimizer, fitting step, or training API to fit generator parameters to target weights.
- Decoded values are generated from the encoder network rather than restored model values. One-dimensional targets become zeros, and tensors with rank other than one or two are omitted.
- `decode_model()` returns generated state tensors rather than rebuilding the original architecture or returning a model instance.
- The reported parameter-count ratio is not a measurement of file-size compression and says nothing about reconstruction quality or model behavior.
- The declared wheel build omits the Python module, and no CLI is provided.
